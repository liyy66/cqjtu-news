# 重庆交通大学官方资讯助手

一个聚合重庆交通大学官方资讯的网站，包含 **AI 问答 / 新闻推送 / 新闻查询** 三个模块，
所有内容均来自学校官方渠道，每条问答和新闻都可点击跳转官网原文核对。

## 线上地址

https://cqjtu-news.app.workbuddy.host/

## 三个模块

| 模块 | 能力 |
|---|---|
| **AI 问答** | 输入关键词（如"博士点""学费""就业"）在 28 条官方问答中检索，答案下方标注信息来源与原文链接，点击即跳转官网核对 |
| **新闻推送** | 默认展示最新一天新闻，可按日期前后翻页、按 12 个栏目筛选；点击新闻在站内阅读全文，右上角 ↗ 跳转到官网原文 |
| **新闻查询** | 支持关键词全文检索历史新闻，或选择日期精确查询当天全部新闻；同样可站内阅读全文并跳转原文 |

## 数据规模

- **2408 篇**官方新闻全文（含配图），时间跨度 **2019-01-03 ~ 2026-10-12**，覆盖 898 个发布日期
- **28 条**官方问答，覆盖学校概况、学科专业、人才培养、招生就业、组织机构、校园服务
- **12 个**新闻栏目：时政要闻、党建工作、科学研究、合作交流、人文交大、招生就业、学院动态、信息通知、学术信息、招标信息、逍遥学子、媒体交大

## 目录结构

```
site/                    前端站点（部署目录）
  index.html             单文件应用，含全部样式与逻辑
  data/
    index.json           概览：统计、日期列表、栏目、官方链接
    index-all.json       全量轻量索引（搜索用，延迟加载）
    qa.json              问答库
    feed-YYYY-MM-DD.json 每日新闻分片
    articles/pXXX.json   正文分片（每 40 篇一包）

data/                    抓取缓存
  news.json              新闻全文库（2408 篇）
  qa.json                问答源文件
  _list.json             列表页缓存
  _last_update.json      最近一次更新报告

scripts/
  crawl_news.py          爬虫（list / front / body 三种模式）
  daily_update.py        每日增量更新入口
  build_site.py          打包前端分片（去重 + 标题清洗）
```

## 每日自动更新

**已启用定时任务「交大资讯助手每日更新」，每 6 小时自动检查一次**
（约 02:13 / 08:13 / 14:13 / 20:13）。

之所以一天查 4 次而不是固定早上一次：学校新闻经常下午才发，
单次早班抓取容易漏掉当天大半内容。多查几次配合"有更新才动"的策略，
既能及时补上，也不做无意义的重复发布。

流程为：抓取 12 个栏目首页 → 增量补抓新增文章正文 → 重新打包 →
**有新文章才重新部署上线**。若某次检查官网没有新文章，跳过发布，
不浪费流量也不覆盖线上现有内容。

### 失败会自动重试

`daily_update.py` 采用增量续传设计：抓取失败的条目**不写入** `news.json`，
下次运行会重新抓取。网络中断、服务器限流导致的失败不会造成数据丢失，
也不需要手动重建数据文件。

### 为什么需要"重新发布"这一步

站点是纯静态网页，数据打包成 JSON 文件。抓取只更新本地文件，
必须重新部署才能让线上链接读到新数据。所以自动化的最后一步是发布动作。

### 手动执行

```bash
# 完整一键（抓取 + 增量 + 打包）
python scripts/daily_update.py
node scripts/update.js

# Windows 批处理（等价于上面）
scripts\run_update.bat

# 分步
python scripts/crawl_news.py front     # 抓 12 个栏目最新列表
python scripts/build_site.py           # 重新生成分片
```

### 运行报告

每次运行写入 `data/_last_update.json`：

| 字段 | 含义 |
|---|---|
| `total` | **线上实际展示条数**（已去重，与站点一致） |
| `rawTotal` | 抓取库原始条数（与 `total` 的差值即去重掉的重复量） |
| `newFetched` | 本次**真实成功入库**的新文章数（网络失败时不计入） |
| `failed` | 本次抓取失败、下轮会重试的条目数 |
| `newestDate` | 最新文章日期 |

### 增量与续传机制

- `data/news.json` 中已入库的文章**不会重复抓取**，只对新增 URL 抓正文
- 抓取失败的条目**不写入**数据文件，下次运行自动重试
- 每 40 篇落一次盘，进程中断后重跑自动跳过已完成部分
- 标题自动去除 `-重庆交通大学新闻网` 后缀
- 打包阶段按「标题 + 日期」去重，同文多栏目重复推送只保留一条

## 技术要点

- **零依赖部署**：纯静态站点，Python 内置服务器即可托管
- **移动端优先**：响应式布局，适配微信 / QQ 内置浏览器
- **按需加载**：问答与推送首屏只加载 57KB，1.2MB 的搜索索引延后加载；
  正文按 40 篇分片，站内阅读时才加载对应分片
- **编码处理**：站点为 UTF-8，抓取时直接用 bytes 交给 BeautifulSoup 解析，
  避免 `apparent_encoding` 误判导致中文乱码
